OpenClaw vs Hermes 核心差异

维度 OpenClaw Hermes v0.10.x
设计理念 Linux 原子能力，显式控制 Rails 开箱即用，默认即最佳
安装与配置 npm install -g openclaw，多步配置 curl 一键脚本，hermes setup 交互向导
平台接入 gateway + channels 命令配置 hermes gateway setup 交互式配置
Skill 生态 ClawHub 技能市场，5400+ skills 内置 100+ skills，自动保存工作流为 skill
记忆系统 MEMORY.md + USER.md 文件式 内置记忆 + Honcho/mem0 外部 provider
CLI 风格 显式子命令（openclaw agents list） 自然语言偏好（hermes skills search）
备份迁移 手动复制 ~/.openclaw 目录 hermes backup / import 一键备份恢复

注：两者均支持 Dashboard、Cron、MCP、多平台 Gateway、浏览器自动化等功能，差异主要在实现风格和默认配置。

常见失败场景

原因

OpenClaw 未安装或未加入 PATH。

解决方案

which openclaw 检查路径；如已卸载，手动复制 ~/.openclaw/config.yaml 到 ~/.hermes/

原因

Token 过期或 webhook 未更新。

解决方案

重新获取 Token；运行 hermes gateway setup <platform> 重新配置；用 /debug 检查连接状态。

原因

Key 格式不兼容或 base_url 丢失。

解决方案

hermes auth list 查看是否导入成功；手动编辑 ~/.hermes/config.yaml 补全 base_url。

原因

网络不稳定或旧配置文件过大。

解决方案

按 Ctrl+C 取消后重试；或分批迁移：先迁移 config.yaml，再迁移 .env 和 skills。

原因

压缩包格式不对。

解决方案

确保是 .zip 格式；如为 .tar.gz，先解压再重新压缩为 zip。
